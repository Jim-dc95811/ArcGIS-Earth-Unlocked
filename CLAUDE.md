### Architecture in one picture

```text
Foundation maps  -> what the world looks like          (TPKX)
Operational data -> what databases know about it        (Parcel100, PointLayer)
EarthStick       -> how the user moves through it
Object Factory   -> intentional objects and meaning placed in it
ArcGIS Earth     -> the common renderer
```

**Foundation = stable geography. Layers = changing information.** Never rebuild a big foundation map because one object changed. **Offline first**: online links are optional extensions.

**Sky layout rules (learned v8-v19 - follow them for every future sign, menu, clue):**
1. Put signs and menus **several km out** - near objects shift and pile up as the pilot moves; the trigger reaches any distance.
2. Put them **in the sky** (above about +1 deg): from flying height the horizon is at eye level and anything lower sits on busy imagery.
3. A board must **fit the ~78 deg view**; split long lists into rows ~4 deg apart; never a single vertical column (each name lands beside the star above it).
4. Keep clear of **rings and their names**; ignore what is behind the arrival point.
5. **Check with `preview_view.render()` / `overlaps()` / `below_horizon()` before Jim flies.**
6. Version everything - gate packs and test files carry the version in file and layer name.

**Gate alignment - how and why (EarthStick 1.3.4 + World Gates v21, 2026-11-05; all accepted live).**
- *The real problem (found by Jim flying):* EarthStick flies LEVEL - forward keeps the height, only buttons 3 (climb) / 4 (descend) change it. So the crosshair is the travel path SIDEWAYS only; tilting the view moves the crosshair up/down but not the path. Pilots line the crosshair up on a ring and pass over or under it. Height is the only missing cue.
- *Dead ends (do not redo without a new reason):* (1) attitude 'laser' beam out of the nose (TEST-TEST3): a beam along the line of sight is seen end-on = invisible from the pilot's seat; API **graphics** drape on the terrain (z ignored); API **drawings** keep z but flash a cyan 'just added' highlight on every re-add, so no live line. (2) v20 approach arrows on each ring axis: answered a question the pilot doesn't need ('this isnt really helping'); `approach_arrow()` stays unused in make_gate_kmz.
- *Square gate (v21 look):* gold square, **half-side a = radius / sqrt 2** (corners on the trigger circle, so every point inside the square really fires), four gold legs from the corners straight back along `facing` (exit side), red square 10 m behind (no legs). One-gate demo used 640 m legs (320 m looked too subtle in preview); Jim then asked for half the demo, so the pack uses **320 m**. Gate Maker 1.1 scales legs **1.42 x radius** (= 320/225): Small 71 m, Medium 178 m, Large 320 m. What the pilot sees: side-on = a 3D box/tunnel (mouth and axis obvious); lined up = an even X of legs; high = legs show from the bottom corners; off to one side = legs lean the other way. Labels unchanged (name at radius + 40 m to the right, eye-alt line 130 m below, 20,000 ft LOD). EarthStick arrives 300 m on the GOLD (approach) side of the partner, facing away, so the legs never box in an arrival.
- *Which ring counts (`ring_ahead`, shared by light and beam - 'ring separation', Jim):* nearest gate with horizontal distance 1 m-10 km (`RING_LIGHT_RANGE_M`), bearing to it within **15 deg** of heading (`RING_LIGHT_CONE_DEG`), and gate `facing` within **60 deg** of heading (`RING_LIGHT_FACING_DEG`; gold side toward you - only forward passes fire). Flat-earth east/north from the camera (`e = dlon*R*cos(lat)`, `n = dlat*R`), bearing `atan2(e, n)`. Hub check: 8 rings 3 km apart never cross-trigger (v19/v21: 22 rings x 6 approaches = 132 PASS).
- *Green light:* **|camera z - gate alt_m| <= 0.5 x radius** (`RING_LIGHT_TOLERANCE`): World Gates 225 m radius = +-112 m = +-370 ft; Gate Maker Medium +-205 ft, Small +-80 ft. Both heights are sea level (eye alt). '● RING HEIGHT' #39ff4a, one line above the readout, placed from the readout text's bbox; canvas 1000x320; updated on the 0.10 s status cadence (no extra API calls).
- *Tractor beam (`tractor_pull(next_cam, gates, dt, travel_m, zoom_dir) -> (locked, moved)`, runs before the gate check):* same ring_ahead; acts within **1,500 m** (`TRACTOR_RANGE_M`) and **|gap| <= 1.0 x radius** (`TRACTOR_CAPTURE`); off while 3/4 are pressed (`zoom_dir != 0` - that is how the pilot breaks free). Per step: **frac = max(1 - 0.5^(dt / 1.0 s), min(1, travel_m / distance))**; z += gap x frac. First term = half the gap per second (hovering: 234 ft -> 116/58/29/15/7 ft); second = a straight glide path that reaches zero gap exactly at the mouth (so 668 m/s still arrives centred). |gap| <= **0.3 m** (`TRACTOR_SETTLE_M`) = locked, nothing sent. Idle branch PUTs the held camera only when the beam moved it (no gates = byte-identical to 1.3.3). Light shows '● LOCKED ON' while locked. Sim: 40/300/668 m/s from -150/+200 m -> through within 0.3 m of centre; outside capture (-260 m on a 225 m ring) not grabbed.
